# Contributing to KiriChess

Issues and pull requests are welcome. By opening a pull request you license your contribution under **Apache-2.0**, same as the rest of the software. Rule changes are made in `config/kirichess.rules.json`, which regenerates `docs/RULES.md` (do not hand-edit the generated file, see [`docs/README.md`](docs/README.md)); a pull request touching either is licensed under **CC BY 4.0** instead for that part. Audio in `ui/public/sounds/` is CC0 board-move cues plus original outcome cues; do not drop unlabeled third-party sounds there. There is no CLA and no DCO sign-off required: contributors are taken at their word that they can license what they submit.

Please read the [Code of Conduct](CODE_OF_CONDUCT.md). Security issues: [SECURITY.md](SECURITY.md), not a public issue.

## Layout

| Path                          | What                                                             |
| ----------------------------- | ---------------------------------------------------------------- |
| `src/KiriChess.Engine/`       | Pure chess + clock economy                                       |
| `src/KiriChess.Server/`       | ASP.NET Core API, SignalR, EF Core                               |
| `ui/`                         | Next.js App Router (package name `"web"`)                        |
| `tests/`                      | xUnit / Vitest                                                   |
| `e2e/`                        | Playwright                                                       |
| `config/kirichess.rules.json` | Single source of truth for rule numbers                          |
| `.claude/rules/`              | Project conventions (backend, frontend, engine, security, tests) |
| `docs/`                       | Human docs - start at [`docs/README.md`](docs/README.md)         |

Do not use the old template names `backend/`, `frontend/`, or `web/` as directories.

## Setup

1. Copy `.env.example` to `.env` and set `Jwt__Key`.
2. `docker compose up`, or run the API and `ui/` separately as in the root [README](README.md).

CI and the Docker images build against Node 20 and .NET SDK 10.0.x; match those locally. The npm
version matters more than it looks: `ui/package-lock.json` was written by npm 10.8.2, and a
lockfile regenerated by a newer npm (11.x) resolves differently, so a local run can be green while
every container build breaks on the same change. Do not run `npm install`/`npm ci` with a newer
npm against this lockfile.

## Before you open a PR

On Windows, run the commands below one per line in PowerShell, or use Git Bash: `&&` is not a
statement separator in Windows PowerShell 5.1 and the chained form below is a parser error there.

```bash
dotnet test KiriChess.slnx
cd ui && npm run lint && npx tsc --noEmit && npm test && npm run build
cd ui && npm run gen:api:check
```

Cross-page changes are also covered by `e2e/` (Playwright against the production Docker Compose
images, `cd e2e && npm test`, needs Docker). It is not part of the checklist above because it
takes Docker and about twenty-five minutes, but CI runs it on every PR and blocks on it.

If you change HTTP endpoints, export OpenAPI and regenerate the client:

```bash
dotnet run --project src/KiriChess.Server -- --export-openapi docs/api/openapi.json
cd ui && npm run gen:api
```

If you change `config/kirichess.rules.json`:

```bash
npm --prefix ui run gen:rules
```

Do not commit `.env`, secrets, connection strings, or API tokens. `.env.example` is the only env file that belongs in git.

## Conventions

Match the files next to the one you edit. Feature-oriented server layout, generated OpenAPI client (`ui/lib/api.generated.ts` - do not hand-edit), no hand-written HTTP DTO mirrors in `ui/lib/types.ts`. The longer form is in `.claude/rules/`.
